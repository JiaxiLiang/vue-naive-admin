应用启动流程

main.js bootstrap()
① createApp(App)
② setupStore(app)  Pinia + 持久化
③ setupDirectives(app)  权限指令
④ await setupRouter(app)  注册 4 个守卫
⑤ app.mount('#app')
⑥ setupNaiveDiscreteApi()

一次路由跳转

  1. page-loading-guard 开加载
  2. permission-guard 校验登录态，未登录 → /login
  3. 按 permission store 动态 addRoute
  4. tab-guard 维护多标签页
  5. page-title-guard 改标题
  6. 渲染 layouts + views

关键依赖规则

  • 单向依赖：views → layouts → components → composables → store → api → utils
  • 守卫只读 store，store 不 import router
  • 接口就近：views/**/api.js，只经 request 发请求
  • 业务数据不进 store
  • 错误处理收口在 helpers.js

三层蛋糕（CRUD 封装）

  1. naive-ui 零件
  2. components/me 半成品（MeCrud / MeModal）
  3. views 业务页：只写配置 + 接口函数

运行时数据流：一次「新增 / 编辑保存」

业务页面→ useCrud.handleAdd / handleEdit→ MeModal.open() + NForm 校验→ views/**/api.js doCreate / doUpdate→ request 拦截器：附加 Bearer Token→ 后端 API→ code ∈ [0,200] 放行 / 异常 resolveResError→ 提示 + 刷新列表（MeCrud.handleSearch）
401 / 11007 / 11008 → 带防重复锁的「重新登录」确认框；403 / 404 / 500 → $message.error 中文提示。

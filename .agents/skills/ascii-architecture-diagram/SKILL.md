# 项目运行蓝图（全边框分层架构图）

产出不是目录树，是**运行蓝图**：回答"这个项目是怎么跑起来的"——从启动装配到一次导航/一次请求，每一层的运行机理 + 层与层之间传什么。三条铁律（违反任意一条即返工）：

1. **事实必须经仓库核实**：文件名、端点、端口、路由条数、守卫个数、import 边数，全部 grep/read 过才许写进图里，禁止编造。
2. **排版必须经 `scripts/render.py`**：中文按 2 显示列、程序化补边框；产出前超宽行必须为 0（渲染器超宽时 stderr 报警并以退出码 1 结束）。
3. **盒内每一行都带左右边框**：表格、代码片段一律走 spec 的 table item / lines 管道，裸行拼接 = 边框缺失；连接线注释显示宽度不得超出盒宽。

## 三类产出（按用户诉求选择，可组合）

| 产出 | 适用诉求 | 骨架 |
|---|---|---|
| 整项目全边框分层图 | "整个项目怎么跑" | 运行时序分层，层内=装配台阶/决策树/分诊链 |
| 模块五层图 | "这个模块（store/http/…）怎么跑" | 装配 → 账本/契约 → 核心逻辑线 → 支撑者 → 全生命周期 |
| 项目树状图 | "项目结构+每文件职责" | 真实文件树 + 对齐注释列 + 实测统计 |

## 模块五层模板（store/http 等"一个目录怎么跑"的成熟骨架）

自上而下（按真实模块裁剪，不硬凑）：

1. **装配**：入口函数的初始化台阶 ①②③，写清"图纸 ≠ 数据"的实例化时机。
2. **账本/契约**：一实体一行的表格（存什么/谁来写/谁在读/存活期）或类型契约清单。
3. **核心逻辑线**：模块里真正值得展开的 1~3 条数据流，画成管道/分叉树/汇流线。
4. **支撑者**：helper/工具/注入缝——"在目录里但不是仓库"的身份差异单独一层。
5. **全生命周期**：登录/刷新/登出式的一条条横向链，末行写闭环。

## 图形化精简（用户明确偏好：少文字，多图示）

说明句压成短语，数据流交给图元。六种标准图元：

- **管道**：`后端 ─api.getUser──> [getUserInfo] ─重组─> user 库`
- **分叉树**：`├─ 条件 > 动向`（树状层级表达处理分支）
- **扇出**：`起点 ──┬─> A ├─> B └─> C`（一指多，如清场线五库连环清）
- **汇流线**：多条分支在同一显示列用 `┐│┤▼` 合并进一个分诊点——**同一列必须同一 col 值**，用 lines 的 `text`+`at` 定位（见 spec），禁止手数中文宽度。
- **判定树**：`是 ──> ... / 否 ──> ...`（二分决策点单独成行）
- **生命周期链**：`登录链  setToken > 过闸 > 入库 > addRoute > 首页`，每链一行，链间用名词对齐。

每层只留一句机理注脚（如"防乒乓：重放带 skipAuthRefresh"）；表格一行一实体；全文说明行与图示行比例 ≤ 1:3。

## 范式：一张总图 = N 层全边框盒子 + 层间连线

```
┌──────────────────────────────────────────────┐
│                【工程启动层】                  │
│   pnpm dev ──▶ Vite Dev Server（端口 3200）   │
│      ├── 加载 .env → 注入 import.meta.env     │
└──────────────────────┬───────────────────────┘
                       │ 浏览器访问 http://localhost:3200
                       ▼
┌──────────────────────────────────────────────┐
│           【应用引导层  main.ts】             │
│   bootstrap() 装配序 (1)…(7)，含 ★ 机制标注   │
└──────────────────────────────────────────────┘
```

- **层名** = 运行阶段 + 真实入口文件（如 `应用引导层  main.ts`）。层是运行时序，不是目录名。
- **层内机理**用三种标准范式表达（8~16 行/层）：
  - **装配台阶**（启动/初始化类）：按执行顺序写"台阶A/B/C"，每台阶 = 做了什么 + 产物是什么。
  - **决策树**（守卫/分支类）：`├─ 条件 → 动向`，标注唯一决策者与纯副作用者（※ 注释）。
  - **分诊链**（拦截器/管道类）：按数据流画分支，成功/失败/兜底三条路齐全，防死循环机制单独一行。
- **层间连线**：上层底边 ┬ 打孔 + `│ 注释`（1~2 行，说明"传给下层的是什么"）+ `▼`。下层支撑上层时用 `▲`。跨层引用用 `>>>触发<<<` 与 `★`，重要机制在层内用 `├─` 子树展开。
- **枚举型内容**（布局族/路由表/插件清单）用嵌套小表格（spec 的 table item），渲染器保证内竖线对齐。

## 工作流

### 第 1 步：核实事实

1. `find`/`ls` 全量文件清单（排除 node_modules/.git/dist 等产物目录），重点读：构建配置、入口 main、路由与守卫、store、网络封装、类型地基。
2. 用 grep 数出图里要用的**每一个数字**：静态路由条数、守卫个数、端口、import 边数。禁止写没读过的文件名。
3. 留意同一层的平台/环境分支（条件编译、.env 差异）——信息量最大的部分，必须体现。

### 第 2 步：归层

按**运行时序**自上而下分层（参考，按项目裁剪，不硬凑）：

```
工程启动 → 应用引导 → 装配层（路由/守卫/DI） → 运行层（守卫决策/事件循环） → 渲染层（布局/页面） → 网络层 → 状态层
```

### 第 3 步：填机理

每层套三种范式之一；每行 ≤ 盒宽-4 显示列；写"怎么跑"（步骤/分支/产物），不堆名词。

### 第 4 步：写 spec 并渲染

```bash
mkdir -p .task-artifacts/$(date +%F)
python <skill基目录>/scripts/render.py .task-artifacts/$(date +%F)/<图名>-spec.json > .task-artifacts/$(date +%F)/<图名>.txt
```

spec 与渲染输出一律落在 `<项目根>/.task-artifacts/<日期>/`（file-hygiene 全局规范，**禁止写系统 Temp**）；终稿 stdout **原样**放入 ```text 代码块，不要手改。退出码 0 且无 OVERWIDTH 才算过；有则精简该行文字重渲。

### 第 5 步：自查

边框连续无断行、连接注释在盒宽内、每层讲清"怎么跑"、层间讲清"传什么"、数字可溯源。

## spec 结构

```json
{
  "width": 78,
  "conn": 31,
  "items": [
    { "type": "layer", "title": "工程启动层", "tee": true, "lines": [
        "   pnpm dev ──▶ Vite Dev Server（端口 3200）",
        "      ├── 加载 .env → 注入 import.meta.env",
        { "table": { "widths": [13, 15, 16, 12],
                     "headers": ["empty", "normal", "full", "simple"],
                     "rows": [["登录/403/", "侧栏+顶栏", "全屏侧栏模式", "极简模式"]],
                     "indent": 2 } },
        { "text": "    └─ 其他 code ─────────────┐",
          "at": [[42, "┐"]] }
    ]},
    { "type": "conn", "texts": ["浏览器访问 http://localhost:3200"] },
    { "type": "layer", "title": "应用引导层  main.ts", "lines": ["   bootstrap() 装配序"] },
    { "type": "tree", "col": 29, "rows": [
        { "p": "", "n": "1-vue-naive-admin", "c": "根目录 | Total: 459 files, 16,950 code lines" },
        { "sep": true },
        { "p": "├─ ", "n": "build", "c": "自定义构建脚本目录 | 4 files, 57 code lines" },
        { "p": "│  ├─ ", "n": "index.ts", "c": "构建入口：整合自定义构建逻辑" },
        { "blank": true }
    ]}
  ]
}
```

- `width`：盒宽，默认 78（总宽 ≤ 80 列，窄视口不折行）。`conn`：连线所在显示列，默认 31。
- `layer.tee: true`：底边在 conn 列打 `┬` 供连线穿过；**最后一层不加**。
- `conn.arrow`：默认 `▼`；下层支撑上层用 `▲`；不要连线时传 `""`。
- `lines` 内可嵌 table item（枚举型内容）；widths 按"最宽单元格显示宽 + 2"设定，中文按 2 列。**列宽先列式预算**（如 `2+13+1+14+1+15+1+12+1+16=76`），单元格超宽渲染器报错。
- `lines` 内 `{"text": ..., "at": [[col, "┐"], ...]}`：text 照常补边框后，把 at 里的 [显示列, 字符] 打到行上——用于汇流线（┐│┤▼ 同列合并进分诊点）。col 从行首（含左边框）起算；**同一条汇流线的每一行用同一个 col 值**，落在中文中间渲染器会 stderr 警告。
- `tree`：无右边框树状图。`col` 为注释起点显示列；rows 元素三选一——`{"p","n","c"}`（前缀+名字+注释）、`{"sep":true}`（输出 `│` 段分隔）、`{"blank":true}`（空行）。树行豁免盒宽检查，但注释建议 ≤ 100 列。**统计数字必须实测**：文件数 `find | wc -l`，代码行 `grep -cve '^\s*$'`（非空行），并在图外注明统计口径。

## 质量自查（渲染器只保证对齐，以下需人工判断）

- [ ] 每层讲清"怎么跑"（有机理，不是名词堆砌）
- [ ] 层间讲清"传什么"（连接注释有信息量，不是装饰）
- [ ] 文件名/数字全部来自仓库核实；树状图统计口径已在图外注明
- [ ] 连接线注释 ≤ 盒宽；盒内无裸行
- [ ] 汇流线的 ┐│┤▼ 全部同列（渲染无 WARN）
- [ ] 图形化占比：说明行 : 图示行 ≤ 1:3，六图元优先于散文
- [ ] 关键机制有 `★`/`※`/`>>> <<<` 标注与跨层引用
- [ ] 总宽 ≤ 80 列

## 常见错误

- 手绘对齐、手数中文宽度——必须用渲染器（中文 2 列，手数必错）。
- 编造文件名/数字；只画目录结构不画运行逻辑；统计数字拍脑袋不实测。
- 盒内裸行（表格/代码块忘走 lines/table 管道）——边框缺失的根源。
- 连接线注释超盒宽——窄视口折行后就是"右边不齐的乱串"，宁可精简文字。
- 汇流线各行 col 值不一致、或 col 落在中文字符中间——渲染 WARN 即返工。
- 层内罗列文件名却不写机理；层与层之间只有箭头没有注释。
- 把图写成散文——用户要"直观看出架构"时，文字必须让位给管道/分叉/汇流图元。

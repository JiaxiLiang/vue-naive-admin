# 坐标推导式学习法

把"读懂一个陌生代码/模块"变成一条可推导、可验证的学习坐标：**快 → 构 → 求 → 链 → 推 → 比 → 标 → 封**。

**核心原则（不可妥协）**：
1. 目标是**能推导**（凭需求与依赖关系重建出实现），不是**能背**（记忆源码文本）。
2. **没有经过"合上代码硬写一遍 + 次日复写"输出验证的，一律不算掌握**。
3. 每一处与原项目的差异，都必须**归因到某个需求**，而不是归因到"我没想到"。

## 何时启用

- 用户说"我想学 xxx 模块 / 带我走一遍 xxx / 用我的方法分析 xxx"。
- 用户讨论学习方向、学习路线、如何啃开源项目、如何巩固某层。
- 需要判定"某个文件/函数到底掌没掌握"时，用第 ⑧ 步的封印测试收口。

## 工作流程

```
- [ ] ① 快  基础语法快速过，不纠结，留到项目里巩固
- [ ] ② 构  上帝视角列框架 + 挑关键节点，标注全局数据"从哪进/从哪出"
- [ ] ③ 求  对每个关键文件双向求：向上(删除法定需求) + 向下(依赖失效点)
- [ ] ④ 链  四层想全才动笔：需求 → 技术选型 → 数据契约 → 代码落地
- [ ] ⑤ 推  先写异常预判，再合上代码凭推导硬写(伪代码 + 核心真代码)
- [ ] ⑥ 比  对照原项目找差距(边界/参数/命名三类) + 异常分支做差集归因
- [ ] ⑦ 标  第二遍重写，对标完善度，标准仍是"能推导"
- [ ] ⑧ 封  次日复写封印；未通过输出验证不得宣布掌握
```

引导时依次推进，每步产物写下来交给用户确认，再进下一步。用户只想走某几步时尊重其选择，但⑤⑥⑧三步是"掌握"的最低闭环，不能省略。

### ① 快：语法层快进

基础语法（ES6 解构、箭头函数、`?.`/`??`、组合式 API 等）遇到就一句话点过，**不展开、不纠结**，标注"到具体项目再巩固"。此步不产出图，避免在语法细节上消耗学习节奏。

### ② 构：先框架后节点，不通读

1. 上企业级开源项目，先站上帝视角列出**分层框架**（入口 → 编排 → 原子能力 → 基础设施）。
2. 顺手在框架图上标一句：**全局数据从哪进、从哪出**（唯一事实源在哪、谁读它谁写它）。
3. 从框架里**挑关键节点**（被多处引用/卡在数据主链路上的文件/函数），不逐文件通读。

产物：分层框架图 + 关键节点清单（每个节点标一句"数据进/出"）。

### ③ 求：每个关键文件双向求

- **向上（重建需求，删除法）**：先假设"删了它会怎样？"→ 推出它为谁服务、解决什么问题、崩了会影响哪些上游。
- **向下（查依赖，失效点法）**：梳理它靠什么才干得了这活；对**每个依赖**问一句"它若不在，本模块会在**哪一步**失效"。

产物：每个关键文件一行——`需求(为谁解决什么) | 依赖清单 | 各依赖缺失时的失效点`。

### ④ 链：四层想全才动笔

按顺序把每个要写的模块补齐四层，缺任一层就回到 ③ 继续求：

1. **需求**：它解决什么问题、谁触发。
2. **技术选型**：为什么是这个方案而不是别的（对应到具体约束）。
3. **数据契约**：进什么、出什么、中间态存哪。
4. **代码**：怎么落地（此处才允许看实现）。

产物：四层链表（需求 → 选型 → 契约 → 落地）。

### ⑤ 推：先异常预判，再凭推导硬写

1. 动笔前**不看原码**，凭理解列出"我认为它该处理哪些失败分支"（异常预判清单）。
2. **合上代码**，凭推导（不凭记忆）自己硬写一遍：先用伪代码捋思路，再落核心几行真代码。

产物：异常预判清单 + 用户的伪代码/骨架代码。

### ⑥ 比：对差距 + 对异常做差集

- **对差距**：对照原项目，**只找三类差异**——① 边界处理 ② 参数设计 ③ 组织命名；每处差异必须说出**是哪个需求逼出来的**。
- **对异常分支（差集归因）**：把 ⑤ 的预判与原项目实际分支求差集：
  - 我预判、它也有 → **通过**；
  - 我没预判、它有 → **真盲区**，必须归因到它没被满足的需求；
  - 我预判、它没有 → **过度设计**，想清楚它为何砍掉。

产物：三类差异归因表 + 异常分支差集表（通过/盲区/过度设计）。

### ⑦ 标：第二遍重写

对标原项目的完善度重写一遍，验收标准仍是**"能推导"**——能凭需求与依赖关系把实现重建出来，而不是背下源码文本。

### ⑧ 封：次日复写封印

次日凭记忆+推导复写核心片段。**没经过输出验证的，一律不算掌握**；未复写成功则回到 ⑤/⑥ 定位是盲区还是需求理解偏差。

## 输出格式约定

本 skill 每一步的讲解产物，遵循用户既有格式（除非用户另有要求）：

- **开头**：一句话功能定位 + 调用链文字块（`谁调用 ► 本层 ► 产物去向`，含参数来源、返回值消费方）。
- **中间**：逻辑/时序架构图（ASCII），复杂模块配图，简单函数级可省。
- **结尾**：必须用**一览表**收口——列 = `视角/元素 | 是什么 | 目的`，每行对应一个架构层或分析对象。普通属性对比表不算一览表，不能替代收尾。

## 禁忌

- 严禁通读整项目；② 步只列框架挑节点，全局数据进出必须标出。
- 严禁跳过 ③ 的"向下失效点"直接读实现；依赖缺失会导致误判。
- 严禁在 ④ 四层未齐时进入 ⑤ 动笔。
- 严禁 ⑤ 边看原码边写——必须"合上代码，凭推导不凭记忆"。
- 严禁把 ⑥ 的差异归因到"我没想到"；一切差异归因到需求。
- 严禁在未做 ⑧ 次日复写前宣布"已掌握"。

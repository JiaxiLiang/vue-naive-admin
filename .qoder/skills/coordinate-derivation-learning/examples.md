# 坐标推导式学习法 · 单模块落地示范

以本项目的 `src/utils/http/interceptors.js`（HTTP 拦截器）为例，走一遍完整八步。示范"每步产物长什么样"，供套用到其它模块。

## ① 快
箭头函数、解构、`?.` 一句话点过，标注"到链路里再巩固"。不画图。

## ② 构
```
【请求层】 utils/http/*
  数据进：各 api.js 发出的 request(config)
  数据出：归一化的响应数据 / 统一的错误对象
  唯一事实源：token 来自 store/auth（不在本层存储，只读取注入请求头）
关键节点：interceptors.js（进出必经，被 index.js 注册，被全项目 api 间接依赖）
```

## ③ 求（双向）

向上（删除法）：删掉 interceptors.js → 所有请求不带 token、错误不再统一处理 → 登录后每个受保护接口 401、失败散落到各页面各自 try/catch。催生它的需求 = "横切关注点集中"。

向下（失效点法）：

| 关键文件 | 需求 | 依赖 | 依赖缺失时的失效点 |
|---|---|---|---|
| interceptors.js | 统一注入 token + 归一化错误 | store/auth、$message、axios 实例 | auth 为空→请求头缺 token→后端 401；$message 缺→错误静默 |

## ④ 链（四层）

| 层 | 答案 |
|---|---|
| 需求 | 每个请求自动带 token、每个响应错误收敛成一种形态 |
| 技术选型 | 用 axios 拦截器而非在每个 api 里写：因为约束是"调用方零感知" |
| 数据契约 | 进：config/response/error；出：注入头后的 config、解包后的 data、归一化 error；中间态：无（token 只读不存） |
| 代码 | 此时才打开 interceptors.js 看实现 |

## ⑤ 推
异常预判清单（合码后先列）：token 过期(401)、无权限(403)、服务端 5xx、网络超时、业务码非 0、响应结构缺 data。
凭推导硬写主干：
```
请求拦截: config.headers.token = authStore.token; return config
响应拦截: 成功 -> 若 code!==0 抛业务错; 失败 -> 按状态码分流(401 跳登录 / 其它 $message.error)
```
写不出"401 具体怎么跳登录"→ 记为缺口。

## ⑥ 比
差异（只三类）：原项目把 401 处理拆进 helpers 而非内联——归因到"多处复用清态逻辑"的需求；我内联了。

异常差集：

| 分支 | 我预判 | 原项目有 | 结论 | 归因 |
|---|---|---|---|---|
| 401 过期 | ✓ | ✓ | 通过 | — |
| 5xx | ✗ | ✓ | 真盲区 | 归因到"后端不可用时给用户兜底提示"需求 |
| 请求重试 | ✓ | ✗ | 过度设计 | 原项目靠统一提示即可，无需重试 |

## ⑦ 标
重写一遍：把 401 清态抽成 helper、补 5xx 兜底、去掉重试。标准 = 能凭"调用方零感知 + 错误归一"两条需求推出结构。

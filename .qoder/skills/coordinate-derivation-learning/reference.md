# 坐标推导式学习法 · 提问模板与产物表

配合 [SKILL.md](SKILL.md) 使用：每一步该问什么问题、产出什么表，这里给可直接套用的骨架。

## ② 构：框架图 + 数据进出标注

分层框架图每层后必须挂一句数据进出：

```
【入口层】  main.js / App.vue          数据进：无   数据出：挂载 app、注册 store/router
【控制层】  router/guards/*            数据进：token、路由表   数据出：重定向/页面清单
【状态层】  store/modules/*            ← 唯一事实源在此，标清谁读谁写
【页面层】  views/**                   数据进：store + api   数据出：用户交互
【请求层】  utils/http/*               数据进：api 调用参数  数据出：归一化响应/错误
```

关键节点筛选标准：被 ≥2 处引用，或卡在数据主链路（进出必经）上。

## ③ 求：双向提问模板

向上（删除法）——对着文件问：
- 如果这个文件整个删掉，最先报错/崩的是谁？
- 它崩溃后，用户侧表现是什么功能失灵？
- 反过来：正是哪个需求催生了它？（一句话需求定位）

向下（失效点法）——对每个依赖问：
- 这个依赖若不存在（返回 undefined / 抛错），本模块会在**哪一行/哪一步**卡住？
- 本模块有没有为这个失效点做兜底？没做是有意还是盲区？

产物表：

| 关键文件 | 需求(为谁解决什么) | 依赖清单 | 各依赖缺失时的失效点 |
|---|---|---|---|
| interceptors.js | 统一处理 token 与错误 | store/auth、$message | 无 auth 则请求头缺 token，鉴权接口 401 |

## ④ 链：四层链表

| 层 | 追问 | 本案答案 |
|---|---|---|
| 需求 | 解决什么问题、谁触发 | |
| 技术选型 | 为什么是这个方案不是别的（对应哪条约束） | |
| 数据契约 | 进什么 / 出什么 / 中间态存哪 | |
| 代码 | 怎么落地（此时才看实现） | |

四层任一空着 → 回 ③ 继续求，不许动笔。

## ⑤ 推：异常预判清单模板

合上代码，先列"我认为它该处理的失败分支"：

```
- [ ] 入参为空 / undefined / null
- [ ] 异步请求超时或网络错误
- [ ] 业务码非成功（401 过期 / 403 无权限 / 5xx）
- [ ] 并发/重复触发（连点、多次进入）
- [ ] 依赖能力缺失（store 未初始化、token 丢失）
- [ ] 边界值（空数组、超长、非法类型）
```

再"凭推导硬写"：伪代码捋主干 → 核心 3~8 行真代码。写不出来的地方 = 掌握缺口。

## ⑥ 比：两类归因表

差异三类（只找这三类，其它不比）：

| 差异类型 | 我的写法 | 原项目写法 | 是哪个需求逼的 |
|---|---|---|---|
| 边界处理 | | | |
| 参数设计 | | | |
| 组织命名 | | | |

异常分支差集：

| 分支 | 我预判 | 原项目有 | 结论 | 归因 |
|---|---|---|---|---|
| token 过期 | ✓ | ✓ | 通过 | — |
| 无权限 403 | ✗ | ✓ | 真盲区 | 归因到"多角色权限"需求 |
| 请求重试 | ✓ | ✗ | 过度设计 | 原项目靠拦截器统一提示，无需重试 |

**归因铁律**：差异只能归因到需求，不能归因到"我没想到"。"没想到"本身要再追一层——是哪个需求我没识别出来。

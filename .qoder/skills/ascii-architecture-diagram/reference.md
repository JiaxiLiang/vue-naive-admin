# 样式规则全文与框线模板

## 一、整体结构

- 按"运行时序"自底向上（或用户指定的自顶向下）分层；层数按作用域实际调整。
- 每层用一个完整矩形框封装，整图放在一个代码块里，宽度不超过 78 字符，中文对齐。
- 图题写在最顶框内首行：`图N【图类型】作用域（一句话说明本图回答什么问题）`。
- 三种图类型的回答对象与主次：
  - 逻辑架构图（核心、必出、信息量最全）：静态组成——谁组合谁、谁返回什么、依赖什么；每层列全文件与导出项，只读此图即可还原模块逻辑组成。
  - 运行逻辑架构图（次要）：动态时序——一次完整闭环里 ①→②→③ 怎么接力；只取一条代表性链路。
  - 分层管道全景图（次要、可省）：上下层关系——数据/控制权如何跨层流动。

## 二、框头格式

`【中文层名】 + 空格 + 该层源码目录或入口文件路径`

例：`【应用引导层】main.js`、`【网络请求层】utils/http/`、`【组合编排层】useCrud.js`

需要细讲的层，路径后加 Obsidian 双链占位：`【守卫运行层】[[守卫运行详图]]`。

## 三、连接符号（制表符）

字符集：`┌ ┬ ┐ ├ ┼ ┤ └ ┴ ┘ │ ─ ╌ ▼ ▲ ► ◄`

**箭头字典（全图统一，图例写在最顶框内供读者对照）：**

| 符号 | 含义 |
| --- | --- |
| `▼ 标签` | 层间下行，箭头与"触发条件或交接物"写在同一行 |
| `▲ 标签` | 反向支撑：下层凭注入/借阅反哺上层 |
| `──►` | 静态依赖：import / 调用 / 数据产出 |
| `╌╌►` | 运行时连接：ref 遥控 / 回调注入 / 借阅（非 import） |
| `►` | 同行步骤链 `A ► B ► C` |
| `◄──` | 反向依赖 / 回流 |

层与层之间（下框承接上框，标签贴着箭头写）：

```text
└──────────────────────────────┬───────────────────────────────────────────┘
                               │
                               ▼ 触发条件或交接物（必填一句）
┌──────────────────────────────┴───────────────────────────────────────────┐
```

反向支撑（箭头朝上，标签同样贴着箭头，箭头下补一段竖干）：

```text
└──────────────────────────────┬───────────────────────────────────────────┘
                               ▲ 下层凭注入/借阅反哺上层
                               │
┌──────────────────────────────┴───────────────────────────────────────────┐
```

- 箭头必须带标签，例：`▼ 用户输入 URL 触发导航`、`▼ 传入 {doCreate, refresh} 触发调用`、`▲ 注入为 doCreate 反哺编排层`。
- 框头行与内容之间加 `├──────┤` 分隔线，让层名与正文分层可见。
- 框内依赖用 `──►`、运行时连接用 `╌╌►`、回指用 `◄──`、步骤链用 `►`；禁止混用 `→ ←`。

## 四、框内表达

- 并列项：`├──`，最后一项 `└──` 收口。
- 严格执行顺序的步骤：标 `①②③④…`。
- 条件分支：`条件 ──► 结果`，例：`无 Token ──► 重定向 /login`。
- 调用链：`A ► B ► C`，例：`组件 ► api.js ► request(axios实例)`。
- 括号 `()` 内放补充说明、参数、举例：`(端口 3200 / 主机 0.0.0.0)`。
- 返回值消费方在 `►` 后注明：`Promise.resolve(data) ► 组件拿到数据`。
- 同级互斥选项（如多种布局/多种粒度）在框内画并排子表格：

```text
│   ┌────────────┬──────────────────────┬────────────────┐
│   │ 列名        │ 列名                  │ 列名            │
│   ├────────────┼──────────────────────┼────────────────┤
│   │ 内容        │ 内容                  │ 内容            │
│   └────────────┴──────────────────────┴────────────────┘
```

- 注释符号可用 `◄─ 说明` 对刚写过的一行做旁注。

## 五、详略与外链

- 主图每层只画"职责摘要 + 关键分支"，不展开内部实现。
- 细讲层用 `[[层名详图]]` 占位，形成"一张总图 + N 张层详图卡片"结构；用户后续发"画出 xxx 文件夹的架构图"即产对应卡片。
- 详图卡片内部才允许出现方法签名、关键判断树、逐步骤 ①②③。

## 六、文字配套结构（图的三明治）

1. 图前：一句话需求定位——本作用域解决什么问题、痛点是什么。
2. 图前：调用链文字块——`使用方 ──import──► 本层`，逐条列真实用法（含参数来源、返回值去向）。
3. 图：按上述规则绘制。
4. 图后：一览表——每文件 `输入 → 交付 → 消费方`（单文件粒度可省）。
5. 图后：2~4 个"值得吃透的设计点"，用 ①②③ 编号成段。

## 七、对齐技巧

- 中文字符按 2 宽度量，框右边界 `│` 允许 ±1~2 字符误差，风格与既有图一致即可。
- 顶边框 `┌` 后 `─` 数量全图统一（推荐 74 个），保持各框等宽。
- 长行宁可拆两行，不可冲出右边界。

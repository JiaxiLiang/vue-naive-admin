# ASCII 分层管道架构图生成

为指定作用域（整项目 / 模块 / 文件夹 / 单文件）生成统一风格的 ASCII 架构图，先讲需求与调用链，再出图，最后一览表收口。

**核心原则：逻辑架构图是唯一主角**——必须一眼看清该作用域的逻辑组成（分层是什么、每层由哪些文件/类/函数构成、谁组合谁、谁依赖什么）。运行时序图、全景图为次要附属，只在逻辑架构图之外补充动态流转，不得喧宾夺主。

## 工作流程

```
- [ ] Step 1: 确定作用域与产出组合
- [ ] Step 2: 通读作用域内全部源码
- [ ] Step 3: 上下层调用关系分析（双向扩散）
- [ ] Step 4: 输出一句话需求定位 + 调用链文字块
- [ ] Step 5: 按样式规则绘图（单一代码块）
- [ ] Step 6: 输出一览表 + 设计要点
```

### Step 1: 作用域与产出组合

| 粒度 | 分层依据 | 核心图（必出、占最大篇幅） | 次要图 |
|---|---|---|---|
| 整项目 | 运行时序：工程启动 → 应用引导 → 路由/入口控制 → 布局渲染 → 页面组件 → 网络请求 → 状态管理（按实际增减） | 逻辑分层架构图（按层展开组成与依赖） | 运行时序图/全景图：仅用户明确要求时补 |
| 模块/文件夹 | 职责分层：装配/出口层 → 编排层 → 原子能力层 → 基础设施层 | 逻辑架构图（每层列全文件、导出项、组合与依赖关系） | 运行时序图：只挑一条最有代表性的链路，宜短 |
| 单文件 | 内部结构分层：导出入口 → 核心类/函数 → 依赖工具 → 原生 API | 逻辑架构图 | 全景图：可省 |

用户只要一张图时只出逻辑架构图；说"精细到这一板块"时按模块详图（卡片）处理。次要图合计篇幅不得超过逻辑架构图。

### Step 2: 通读源码

Read 作用域内每一个文件，禁止只看目录名猜职责。记录：导出项、参数来源、返回值消费方、依赖的第三方能力、自动导入项。

### Step 3: 上下层调用关系分析

- **向上扩散**：Grep 作用域的导出名（函数/组件/单例）在全项目的引用，确定真实消费方与用法（import 路径、调用参数）；找不到引用则标注"暂未使用"。
- **向下扩散**：梳理作用域 import 链与依赖注入项（回调函数、api 方法、实例），直到原生 API / 构建配置层。
- 结论写成两类关系：谁读它/谁写它（借阅关系）、谁注入给它（反向支撑，图中用 ▲）。

### Step 4-6: 输出结构与样式规则

完整规则见 [reference.md](reference.md)。核心摘要：

1. **动笔顺序**：一句话需求定位（解决什么问题）→ 调用链文字块（`使用方 ► 本层 ► 产物去向`）→ 图 → 一览表。
2. **图**：逻辑架构图是图部分的重头——框内要完整列出该层所有文件/导出项及其组合、依赖指向，保证"只看这一张图"即可还原模块逻辑组成；单一代码块；最顶框放图题 + 箭头字典图例；每层一个完整矩形框，框头 =【中文层名】+ 源码路径/入口文件，框头下加 `├──┤` 分隔线；层间 `└──┬──┘` + `│` + `▼ 交接物`（标签与箭头同行，必写一句触发条件或交接物）；反向支撑用带标签的 `▲` 画；框内箭头按字典统一：`──►` 静态依赖、`╌╌►` 运行时连接、`►` 步骤链、`◄──` 回流，禁止混用 `→ ←`。
3. **框内**：并列 `├──`/`└──` 收口；有序步骤 ①②③；条件分支 `条件 ──► 结果`；调用链 `A ► B ► C`；括号放补充说明/参数/举例；同级互斥选项用框内并排子表格。
4. **详略**：主图每层只画"职责摘要 + 关键分支"；要细讲的层在框头加 `[[层名详图]]` 双链占位，后续单独发卡片机。
5. **宽度**：≤78 字符，中文按双宽近似对齐。
6. **收口**：一览小表（每文件：输入 → 交付 → 消费方）+ 2~4 个值得吃透的设计点。

## 禁忌

- 严禁跳过 Step 3 直接画图；调用链不明的模块不得凭注释臆想消费方。
- 严禁在总图中展开某层内部实现细节（那是详图卡片的事）。
- 严禁输出多个代码块拼一张图；整图放一个 text 代码块。
- 严禁用多张次要图（时序图/全景图）稀释逻辑架构图——若多图并存，逻辑架构图必须最先出现且信息量最全。
- 状态管理等层涉及"唯一事实源"叙事时，遵循项目的架构视角规范：讲角色、边界、借阅关系，不罗列字段。
